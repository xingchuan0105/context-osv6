# Rust 前端全站布局对标 Grok · 待确认报告

日期：2026-09-08。状态：方案评审，尚未修改产品布局。范围：Rust 前端全部路由、设置页签、公共弹层和移动端；Next 作为既有产品规则与实现参考，不纳入本次改造执行范围。

## 1. 结论

建议采用统一的「可折叠左导航 + 轻量上下文顶栏 + 单一主内容区 + 按需侧面板」。聊天成为最轻的主场景，工作区在同一骨架中增加资料能力；设置、分享和管理通过对象内导航扩展，而不是每到一个页面就换一套布局。

当前偏移主要是结构问题：顶栏、页脚、独立页面导航和多排输入工具争抢空间。附件按钮缩短只是局部修复；输入区仍需要整体重排。上一轮的字体、颜色、圆角、无溢出检查通过，不能证明布局已经接近 Grok。

本报告以 Grok 网页聊天产品为参考对象；x.ai 营销站、getdesign 的 x.ai 样例、Grok Bot 和 Grok Build 不视为同一个界面。先确认布局方向，颜色和品牌暂沿用现行基线。

## 3. 主要差异与改造建议

下表「方向」是从历史 Grok 参考与本项目任务推导的方案，并非今天 Grok 每个页面的实测描述。

| 优先级 | 当前问题 | 用户体验后果 | 建议方向 |
|---|---|---|---|
| P0 | 全宽品牌顶栏、聊天会话栏、工作区自身顶栏并存 | 导航重复，横向与纵向空间都被占用 | 一套应用壳；全局目的地在左栏，对象操作在轻顶栏 |
| P0 | 聊天初始页有标题/说明、输入标签、附件行、能力行、快捷键说明等多层 | 用户先读操作面板，再开始提问 | 空态只突出一句引导与一个 composer；次要说明渐进呈现 |
| P0 | 附件虽已缩短，仍独占工具行 | 输入框看上去仍像表单 | 回形针入口并入底部工具栏，附件加入后才出现文件条 |
| P0 | 各页面分别组织主导航，工作区资料与会话挤在局部区域 | 切换页面后需要重新寻找返回、会话和资料 | 保持全局导航位置；工作区内部明确区分会话与资料 |
| P1 | 工作区默认固定资料区域，手机上下堆叠 | 阅读区受挤压，聊天可能被推到首屏之外 | 资料按需打开；宽屏侧面板、窄屏抽屉，保留可发现入口 |
| P1 | 设置使用横向换行页签 | 选项多时形态不稳定，手机占高度 | 桌面左分类右表单，手机分类列表进入单页并可返回 |
| P1 | 产品页保留较重的公共页脚与跨场景入口 | 聊天工具感被营销页面结构打断 | 应用内帮助/法律收至账户弱入口，公共页保留页脚 |
| P1 | 会话行、操作按钮、内容卡片大量边框和相近形状 | 所有区域都像按钮，层级扁平 | 导航用轻列表行，内容靠留白分组；边框优先服务输入与浮层 |
| P1 | 管理页导航项平铺换行 | 找业务模块困难，数据空间变窄 | 管理二级导航与主数据区，筛选操作固定位置 |
| P2 | 公开分享、帮助、商业页各自扩展页面头部 | 同一产品缺少一致的空间秩序 | 共享间距与页头规范，按任务采用公开壳/文档壳/交易壳 |

## 4. 统一布局提案

### 4.1 应用壳

桌面左栏建议展开宽 240–256px，折叠宽 56–64px；上下文顶栏建议 48–56px。它们是本项目起始设计值，不是 Grok 测量值。

左栏结构建议：新对话、工作区、最近对话；底部账户入口。全局最近保留普通/工作区来源标识。工作区内切换到该工作区的会话列表，同时保留回到全局的明确入口。设置和帮助留在账户菜单；不把百科、所有设置项或客户端营销链接铺成业务主导航。

顶栏只保留当前对象名称与相关操作。个人聊天不会出现知识库检索；工作区才有资料和分享。通知、账户不再在多个嵌套页头重复出现。升级和充值继续指向现有 canonical，不新增结算路径。

```text
┌──────────────┬──────────────────────────────────────────────┐
│ 收起 / 新对话 │ 当前会话 / 工作区             资料* 分享* 更多 │
│ 工作区        ├──────────────────────────────────────────────┤
│ 最近对话      │                                              │
│ …            │              主阅读 / 操作区域                │
│              │                          ┌──────────────────┐ │
│              │                          │ 按需资料面板*    │ │
│              │                          └──────────────────┘ │
│ 账户          │             composer（聊天场景）              │
└──────────────┴──────────────────────────────────────────────┘
* 仅在支持该操作的对象上出现；个人 /chat 没有知识库资料面板。
```

这会修改现行 IA 中全宽 App top bar、workspace 默认右栏等规则。必须在用户确认后先更新 `PRODUCT_IA.md`，再实现；本报告不直接覆盖现行规范。

### 4.2 聊天：首屏、对话中、附件

- 空态：输入区位于主区域视觉中心偏上，中心依据扣除导航后的可用区域计算，不按整屏硬居中；保留一个简短引导。小高度视口自然顶对齐，避免键盘挤出内容。
- 对话中：正文建议最大宽 720–800px，composer 与正文对齐并靠可用区域底部；消息滚动区独立。用户消息适度气泡化，助手正文主要使用自然阅读排版。
- composer：文本区 + 一条工具栏。左侧附件、联网等真实可用能力，右侧模型入口与发送；空间不足时低频操作进入更多。不得添加未实现的语音、Imagine、Agent 按钮来模拟 Grok。
- 附件：图标按钮具备可访问名称和提示。加入附件后显示名称、解析状态、移除；在文件条附近显示「仅本轮」，详细限制按需展示。保留 Excel/PPT 等已约定办公文件需求，不走知识库检索。
- 状态：上传中、解析失败、超上下文、发送中和中断都有就地反馈；不能用布局收纳把失败原因藏掉。发送后本轮文件不继续注入后续轮次。
- 手机：附件按钮触达区域建议至少 44×44px，视觉图标可以更小；工具行不横向溢出。键盘出现时当前输入和发送可见，长文件名不挤掉移除按钮。

```text
空态                              已有附件
        有什么可以帮你？            ┌──────────────────────────┐
┌──────────────────────────┐       │ [报告.xlsx  就绪 ×] 仅本轮 │
│ 输入问题…                 │       │ 请分析这份表格…           │
│                          │       │                          │
│ ＋  联网       模型⌄  ↑   │       │ ＋  联网       模型⌄  ↑   │
└──────────────────────────┘       └──────────────────────────┘
```

### 4.3 工作区、设置、分享、管理

工作区总览采用同一左栏，主区域为标题/新建、筛选搜索、列表或卡片。不要为「全部/我的/收藏」再创建一套全局导航。工作区内聊天复用同一 composer；资料入口明确呈现文件数和处理异常，有资料也不代表必须永久占满右侧。

设置采用分类导航与内容双栏，分享中心采用对象标题与内部分类，单用途统计页使用面包屑与主内容。管理页沿用空间规范但保留适合数据工作的宽表格，不能为了像消费聊天而将表格挤到 760px。

公开知识库面向访问者：顶栏明确所属知识库与权限；聊天优先进入首屏，资料按需展开。该页面不展示拥有者私有导航。邀请、失效链接、无权限均使用短反馈页，主行动清晰。

## 6. 尺寸、状态与验收方法（确认后执行）

建议测试宽度 390、768、1280、1440px，另加 1280×720 短屏；明暗主题布局相同。聊天正文建议 720–800px、普通表单 560–680px、总览 960–1200px，数据表按剩余空间展开。资料面板建议 320–360px，仅在保留可用正文宽度时并排，否则改抽屉。断点以内容容纳能力校准，不机械复刻未经实测的 Grok 数值。

验收按三类证据分别记录：①路由与功能验证；②布局截图与人工视觉复核；③可获得的 Grok 样本并列比较。任意一类通过都不能代替另外两类。

| 验收项 | 通过条件 |
|---|---|
| 导航一致性 | chat→工作区→设置→返回，主导航不换位；对象操作不混进全局导航 |
| 聊天首屏 | 常用桌面/手机视口可直接看到输入和发送；次要说明不成为主视觉 |
| 附件 | 短入口、长文件名、解析中/失败、移除均可操作；不展示知识库检索；超量明确报错 |
| 连续对话 | 长答复和代码不挤坏壳；滚动与底部输入互不遮挡；停止/重试位置明确 |
| 工作区 | 无资料/处理中的资料/已有资料皆可发现；开关侧栏不丢草稿与会话位置 |
| 设置/管理 | 分类选中与标题一致；表单不会为填满屏幕而拉伸；表格在自身区域滚动 |
| 小屏与可访问性 | 键盘不遮发送；抽屉无穿透；Tab/Esc/焦点返回可用；图标操作有名称 |
| 权限与异常 | 匿名、无权限、失效链接、空数据、长标题、接口失败都有稳定布局 |
| 业务边界 | 个人附件只在本轮；持久知识属于工作区；支付/BYOK保持唯一完成路径 |

## 7. 确认后实施顺序

1. 将已确认的壳、导航、上下文面板规则写入 `PRODUCT_IA.md`；取得可用 Grok 参考后固定样本日期与状态。先做聊天、工作区、设置三张布局样稿，校准比例。
2. 落地公共应用壳和 composer，以个人聊天完成首个端到端切片；检查附件及滚动行为。
3. 迁移工作区、设置、分享及统计；确保资料能力和对象归属不变形。
