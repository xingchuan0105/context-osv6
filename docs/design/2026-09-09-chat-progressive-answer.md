# 纯聊天逐段回答与取消

本批承接长回答超时与嵌入计费修复。用户批准 25–40 分钟的构建、定向测试、少量真实模型验证与本地 API 刷新；不涉及支付、部署或 GPUI。

## 行为与实现

1. 纯聊天使用所选模型原有的 thinking 配置。Quick Chat 配置关闭思考时，循环不再强制开启；配置开启时仍保留。检索与 Lead 合成的阶段策略不变。
2. 纯聊天明确区分工具／技能请求与最终回答。模型输出的最终回答有内部起止边界，宿主只把边界内正文逐段发给浏览器；边界不进入主气泡或持久化答案。
3. 增量解析保留足够长的尾部，跨分片检查内部标记和 UTF-8 字符；供应商协议、宿主观察、工具执行标签不进入回答流。漏掉边界且正文尚未显示时，最多修复一次；仍不合格或边界不完整则报格式错误，不把原始草稿直接放行。
4. 已进入回答通道的代码示例和 JSON 数据不再当作本轮工具／技能请求执行。通道外的执行仍使用原有 ToolCatalog / sandbox 路径。
5. 已逐段发送的正文不在结束时重复发送一整篇；最终答案仍经过现有完整性检查和持久化。取消继续使用 CancellationToken。

提示正文在 `avrag-rs/prompts/loop/chat-answer-channel.md`，代码仅加载；标记已登记。没有新增外部 API 或修改数据库协议。

新增检查包括：边界逐字符切分与中文、多片段增长、协议片段跨界拦截、工具草稿不展示、回答中的代码／JSON 不触发工具、响应完成前已有正文、取消后上游连接关闭，以及真实浏览器正文中途停止和历史重载。

首批真实连续发送发现短回答漏边界，已加入一次格式修复，并以模拟上游验证“成功修复／修复仍失败”均不会展示原草稿或无限重试。最终连续发送通过。
