# Rust 前端：功能、用户意图与实际体验审计

日期：2026-09-08。性质：源码与请求链路审计；不是新一轮线上验收。

## 结论

问题不只在组件样式。个人聊天、工作区问答、公开分享三个场景共享 ChatPage，却没有完整传入各自的数据范围和授权语义；多个页面把“显示成功”或“跳到下一页”当成业务完成。上一轮 UI 改造保留了这些错误边界，旧测试也在验证其中一部分错误行为。

本轮明确的用户意图：

- 个人 `/chat`：快速聊天，不提供知识库检索。
- 个人聊天附件：保留，仅作为本轮直接上下文，不走知识库检索。
- 工作区：资料管理与持久知识问答发生在这里。
- 同一任务只有一个清晰完成路径；控件存在就应有真实、可理解的作用。

个人聊天是否联网没有被本轮要求取消，沿用按需联网；本审计不把“快速聊天”自行扩大解释为禁止一切工具。

## 范围与证据边界

核对 Rust 前台的个人聊天、工作区总览与资料/笔记、公开分享与邀请、设置/BYOK、会员/充值/回跳、全局菜单与通知、登录/重置密码和客户端发现入口；对关键动作追踪到 web-sdk、ChatRequest 或已有后端路由，并阅读对应浏览器用例。

不包含 Admin 管理后台的业务正确性全审、线上权限渗透测试、真实支付、真实模型调用和桌面原生能力验收。未运行新编译或脚本测试。下列“已确认”指源码事实，不能替代线上复现；“待验证”单列。

已先使用 code-review-graph 获取工作区模块摘要，再对具体文件做精确搜索。没有以旧 IA 审计中的 done 状态替代 Rust 实现核查。

## 目标任务矩阵

| 场景 | 用户来做什么 | 可以呈现 | 不应呈现/发生 | 成功依据 |
|---|---|---|---|---|
| 个人聊天 | 快速提问、本轮看附件 | 输入、附件、按需联网、发送/停止 | 知识库开关；附件索引等待；隐式跨轮资料使用 | 请求携带本轮直接附件上下文，不启用 rag |
| 工作区问答 | 基于这个工作区资料回答 | 资料状态、范围说明、问答、引用 | 用个人会话附件数控制工作区检索 | 请求绑定工作区与真实文档范围 |
| 公开分享 | 对别人分享的资料提问 | 分享库名称、允许资料、访客问答 | 借用访客个人聊天上下文、个人工作区导航 | 分享凭据与服务端授权/计费路径正确 |
| 账户设置 | 修改资料或模型配置 | 当前值、修改、保存结果 | 未提交却显示已保存 | 服务器确认后刷新仍保留 |
| 邀请 | 接受这份邀请 | 对象、邀请状态、接受结果 | 用直接进入工作区代替接受 | 成员状态改变且权限可用 |
| 会员与充值 | 获得会员名额或补充余额 | 区分两类购买、真实订单状态 | 会员只能看不能买；未核验就宣布到账 | 订单确认与相应权益/余额更新 |

P1 = 影响核心任务、数据范围或成功承诺；P2 = 交互一致性、错误恢复或可访问性。优先级不是线上事故等级。

|---|---|---|---|---|
| U01 | P1 | `/chat` 明明是快速聊天，却显示点了没反应的知识库入口 | `chat/chat_composer.rs` 无场景判断渲染 ScopeBar；`chat/scope_bar.rs:20` 在 ready_count=0 时直接 return，按钮只根据总体 disabled 显示禁用 | 个人聊天移除知识库入口与相关空态文案，不能只改成灰色 |

## 修复顺序与验证门

### A：先恢复三个聊天场景的真实边界

个人聊天 / 工作区 / 分享访客各自有明确的请求上下文和可用动作；共用展示与流式机制，不复制三套 ChatCanvas 或 Agent 执行管线。上下文来自页面所属对象和授权状态，不能通过附件数量推测。

个人附件需要前后端端到端实现：格式和大小约束 → 解析/读取 → 本轮上下文预算检查 → 构造请求 → 保存该轮可展示记录。超出预算不能静默截断或偷偷降级为 RAG。原件保留时长、格式集合与大文件策略尚需设计，用户已确认的“本轮、不检索”不能因此打折。

验证门：无附件快速聊天；附件发送不创建索引、不发 rag；下一轮不自动注入前轮附件；工作区仅凭工作区资料即可提问；范围选择进入 doc_scope；公开访客请求携带合法分享上下文；跨场景切换不串范围。

### B：消除虚假的成功

修复 U06–U10、U16。验收必须观察后端结果和重新进入后的状态，不能只看 toast/路由变化。真实支付操作需单独安排受控环境，不能在审计阶段创建真实交易。

### C：整理任务入口与错误恢复

工作区列表与资料预览、设置默认页、异步反馈、菜单可访问性、语言完整性、统计口径依次处理。每一项以“用户能完成什么任务”为验收单位。
