# 长回答超时与嵌入计费修复

2026-09-09，本地真实后端验收。用户批准本批构建、定向测试、少量模型调用和本地服务刷新；未执行支付或部署。

## 已修复

### 持续生成仍被总时长超时截断

修复前，同一长文请求在 0.71 秒收到首个过程事件，累计收到 450 个过程流片段，但在 30.08 秒返回 `upstream_unavailable` / `Failed to read chat completion stream chunk`。不是整个请求一直没有上游数据。

LLM 单路由和连接池原先用 reqwest 的总请求 `timeout`，正文持续到达仍会触发截止时间。现在共同使用连接与读取空闲超时：持续输出可超过窗口，连接建立、等待响应头、流中断后的空闲等待仍有上限。取消路径保持原有 CancellationToken。

真实浏览器请求原来的 2000 词长文，约 80.9 秒完成，回答约 2610 词；无 SSE error，收到 done。新增网络测试覆盖持续流跨越超时、流中途停顿、无响应头三种情形。

另一个未指定浏览器模型选择元数据的 API 探针持续 210 秒，收到 3656 个 `reasoning_summary_delta`，未再次发生固定 30 秒截断，但在探针主动关闭前没有正文 token 或 done。这条默认请求路径**没有通过长文完成验收**，不能与浏览器所选模型的成功结果合并宣称全路径稳定。

## 尚未关闭的体验项

后续本地复验已补齐正文逐段显示、正文中途停止与默认 API 长文完成，见 [纯聊天逐段回答与取消](2026-09-09-chat-progressive-answer.md)。以下保留本报告当时的发现，不代表后续状态。

**个人聊天正文逐段展示仍待改造。** 当前 retrieve 流进入过程面板，DirectAnswer 经整篇检查后才进入主回答。此次修复了长回答中断，不能据此声称正文首段延迟或正文已输出后的停止体验已通过。

默认 API 请求的长文完成时延也仍需继续定位；210 秒探针结果是未完成，不是成功。真实浏览器测试日志首轮 `answerDeltas` 辅助计数误用了内部事件名，已改为外部 SSE `token`；此计数未参与通过断言，也不作为逐段展示证据。

后续应明确划分工具／技能请求与最终回答的输出通道，再让已进入回答通道的正文渐进展示。直接把所有 retrieve delta 改成主气泡 token 会让工具代码或协议草稿泄漏，故本批没有绕过现有出站检查。相应验收需新增：首段到达早于 done、持续多段显示、正文中途停止、工具草稿不进入主气泡，以及最终历史与可见回答一致。

模拟测试通过、真实模型完成、用户视觉验收是不同状态。本批没有新一轮用户视觉验收、真机软键盘、真实支付或生产发布。
