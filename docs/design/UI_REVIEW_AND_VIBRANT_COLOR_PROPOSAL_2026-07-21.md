# 第一部分:UI / 视觉语言 / 导航结构 Review（对标 Grok)

## 1. 整体气质

| 维度 | Context-OS(现状) | Grok(对标) |
|---|---|---|
| 气质 | 专业工具 / 编辑器 | 消费级 AI / 轻盈 |
| 密度 | 高：一屏 4-6 个面板、边框多 | 极低：一屏 1 个焦点 |
| 色彩 | 单色墨 + 铜色点缀 | 单色 + 极少量蓝点 |
| 第一屏焦点 | 分散（左栏/聊天/右栏） | 收束到 composer 一个点 |

两者定位不同（Grok 是消费级聊天，Context-OS 是知识工作区，更接近 NotebookLM)，不是谁对谁错。问题在于:**该轻的地方不够轻**(空态、营销面),层级关系被过多边框磨平。

## 2. 配色

- 纪律性好：铜色基本只用于链接、"推荐"徽章、进度条；暗色主题完整度高于 Grok。
- **问题**:铜色同时承担链接、品牌、强调三件事，pricing 页同屏出现推荐徽章 + 协议链接 + 进度条时略有噪点;pricing 页方案描述为英文，与全中文界面断裂（比配色问题更显眼）。

## 3. 字体

- 三套字体（Space Grotesk 标题 / IBM Plex Sans 正文 / JetBrains Mono 代码）可保留，工具感符合定位。
- **正文字号偏小**:body 0.875rem(14px),Grok 约 15-16px 且行距更松；中文 14px 长读偏累，聊天正文建议 15px 起步。
- caption/overline 11px 对中文太小（技术债已登记，属阅读体验问题）。

## 4. 框体与留白

- 大量 1px 边框卡片（dashboard 卡片、右栏面板、设置分区卡）;Grok 几乎不用边框，靠留白和底色分区。**边框太多 = 没有层级**。
- 空态对比典型：Grok 空态 = 视口中心一个巨大 composer；我们空态 = 左栏空 + 中间一行小字 + 右栏两个空面板，**新用户第一屏看到的是三面墙的空**。
- 圆角：Grok 全 pill；我们偏小圆角。体系可不动，composer 和主 CTA 可考虑更大圆角。

## 5. 导航与菜单跳转关系（人机交互）

现状地图:

```
Dashboard                    Workspace                    Settings
  账户 ──┬→ 个人资料 ────────→ (tab=profile)                账单
         ├→ 账单 ────────────→ (tab=billing) ──→ 管理订阅 ──→ /pricing
         └→ 退出登录                                       资料/外观/安全/通知
  logo(Context-OS) ←────────── logo                        返回? 只有页脚小字"工作台"
                              顶栏: 新建工作区/传播/API/外观/个人资料
```

### P0 — 订阅入口埋得太深

- 当前路径：账户 → 账单 → 管理订阅 → pricing,**3 跳**；工作区页（用户停留最久）完全没有订阅/用量入口。
- 对标:Grok 把 SuperGrok 做成首页 hero;ChatGPT 侧边栏常驻 Upgrade。**订阅是商业上最重要的 CTA，应一级可见**。
- 建议:dashboard 顶栏放"升级"按钮（免费用户）或方案徽章；workspace 顶栏同理。

### P1 — 工作区顶栏语义混乱

- "传播"词义不明；"外观""个人资料"是**全局设置项**却出现在工作区上下文，且与 settings tab 重复、命名不一致；"API"是开发者功能与用户设置平铺；"新建工作区"按钮出现在工作区页属上下文错位。
- 建议：顶栏按"工作区上下文操作（分享/API)" vs "全局（外观/账户）"分组，后者收进统一账户菜单。

### P1 — 缺少常驻主导航

- Grok/ChatGPT/NotebookLM 都是左侧栏主导航一条线。我们 dashboard 无侧栏，workspace 左栏只有会话列表——**dashboard ↔ workspace ↔ settings 三个空间之间没有一致的导航骨架**;settings 页没有明显的"返回工作台"。

### P2 — 命名与一致性

- "账单"tab 混装"个人用量"+"账单与计划"，建议改名"订阅与用量"；账户菜单"个人资料" vs settings tab"资料"同物两名;pricing 页登录态仍显示未登录 chrome("登录"按钮）。

## 6. Review 优先级建议

1. 订阅入口一级化（dashboard + workspace 顶栏方案徽章/升级按钮）。
2. workspace 顶栏重构（上下文操作 vs 全局设置分组）。
3. 新会话空态重做（composer 居中放大，空态下右栏让位）。
4. 聊天正文 15px、caption 中文 ≥12px。
5. pricing 页方案描述中文化 + 登录态 chrome 修正。
6. 边框做减法：右栏面板、settings 分区卡改留白 + 浅底色分区。

# 第二部分：鲜活配色方案（Vibrant Color Proposal)

## 1. 方向与原则

用户决策：**放弃"高度对比黑白 + 单一克制铜色"，转向"暖底 + 鲜活主色 + 彩色辅助"**。新原则（用于修订 STYLE_BASELINE §2 的 1-3 条）:

1. **中性带温度** — 灰阶不再是纯灰（0 0% x%)，改为暖纸调：亮色模式是暖白纸面，暗色模式是暖炭底色。面积上中性仍占 ~85%，但底色本身有情绪。
2. **主色鲜活且允许实色 CTA** — 标志色保留 Copper 血统但提升饱和度与明度（橘铜 Tangerine-Copper);**每屏允许一个主行动按钮用主色实色**（升级、新建等），次级按钮保持墨色/描边。
3. **辅助色真正彩色** — success/warning/info/destructive 从"低饱和灰彩"提升为明确可辨的绿/琥珀/蓝/红，用于状态、徽章、进度、计划卡片。
4. **对比度不妥协** — 所有文字/背景组合 ≥ WCAG AA(正文 4.5:1，大字/粗体 3:1)；鲜活靠饱和度和底色，不靠牺牲可读性。
5. **暗色不是反色** — 暗色用暖炭底 + 更高明度的主色，保持同一色温。

## 3. 主色的应用位置（"鲜活"落在哪）

| 场景 | 用法 |
|---|---|
| 主 CTA（每屏≤1 个） | `--accent` 实底 + 白字：升级订阅、新建工作区、新建会话 |
| 次级按钮 | 保持 `--primary` 墨色或描边，不动 |
| 链接/选中态 | 亮色用 `--accent-text`，暗色用 `--accent` |
| 计划卡片（pricing) | Plus = 橘铜描边 + 徽章；Pro 可用 `--info` 蓝做区分色（仅徽章/描边，不铺底） |
| 状态反馈 | success/warning/destructive 新色值，徽章浅底用对应色 + soft 变体 |
| 进度条/用量条 | `--accent`,接近上限切 `--warning`,超限切 `--destructive` |
| 引用 chip / 标签 | `--surface-accent-soft` 底 + `--accent-text` 字 |
| 空态 | 允许主色小面积图形元素（图标/插画色块），不再只有灰 |

**明确禁止**:主色大面积铺背景（>30% 视口）；多主色同屏竞争；彩色实底按钮超过每屏 1 个。

## 4. 迁移计划

> **进度**:Phase 1 已于 2026-07-21 完成（tokens.css 换肤 + sync 到 5 站）。Phase 2 已于 2026-07-22 完成并按用户反馈以**分层策略（方案 D）**修正：高频按钮（新建工作区、发送键）回墨色中性；升级/订阅类（管理订阅、升级 Plus）保留铜色实底但降彩到专用令牌 `--accent-cta`（亮 `22 62% 42%` / 暗 `24 75% 55%`）；链接、tab 选中态、推荐徽章保持铜色。原则修订：每屏铜色实底 CTA ≤1 → **铜色实底只用于低频付费场景，高频生产动作一律中性**（对标 ChatGPT/Claude）。typecheck + 383 测试全绿，截图人工核过。Phase 3 待做。

> **配色变更（2026-07-22）**:用户否决铜色系，经四案比选改用**靛蓝 × 石板灰**（方案一，Linear/Stripe 路线）。tokens.css 已全量换肤：中性色从暖橙调（36/24/26 hue）改冷石板调（220-225 hue)；主色橘铜 `22 85% 45%` → 靛蓝 `235 65% 52%`;`--accent-cta` → `235 55% 45%`;info 改天蓝 `205 85% 48%`；暗色主色 `230 85% 68%`。分层纪律不变（实色 CTA 只用于低频付费场景）。已 sync 到 5 站，组件无铜色硬编码残留，typecheck + 383 测试全绿，亮/暗截图人工核过。同日用户进一步决策：**创建类按钮纳入品牌色**（推翻"高频按钮保持墨色"规则）——新增 `.app-button-create`（亮蓝实底）/`.app-button-create-soft`（浅蓝底）复用类，新建工作区/新建会话/新建笔记为亮蓝实底，添加内容源为浅蓝；logo 胶囊同步改靛蓝（`#3542d4`,favicon/OG/mark.svg 一并改）。体系最终定为：**创建=亮蓝实底、付费=深蓝实底（--accent-cta)、高频行内动作（发送键等）=墨色、次级=描边**。

> **CTA 二次修订 + 布局比例（2026-07-22）**：用户基于 Gemini/Kimi/Grok 三家样例对齐——创建类按钮从亮蓝实底改为**中性灰填充**（`.app-button-create` = surface-soft 底 + foreground 字，`.app-button-create-soft` = 描边幽灵），tab/能力 tag 选中态改浅灰底。原则更新为：**颜色给品牌（logo/链接/状态点/付费），灰度给交互（按钮/选中/hover）**。同期完成三栏比例调整（用户 2560×1600@175%，有效宽 1463px）：左栏默认 280（236-320）、右栏默认 336（280-360）、中栏 ~847（58%），阅读区限宽 44rem（704px）居中，对齐 NotebookLM。

1. **Phase 1（令牌）**:改 `packages/cos-tokens/tokens.css`（亮/暗三块：root、media query、data-theme),跑 `sync.sh`。此时全站立刻换肤，先不组件改动。
2. **Phase 2（主 CTA)**：升级按钮、新建工作区、新建会话改 accent 实底；链接类从 `--accent` 切换到 `--accent-text`。
3. **Phase 3（语义色铺开）**:pricing 计划卡、用量进度条、状态徽章按 §3 表落地。
4. **每个 Phase 的验证门**:`pnpm typecheck` + `pnpm vitest run`;Playwright 亮/暗截图对比（login、dashboard、workspace chat、pricing、desktop);axe 或手算复核 §2 标注的对比度组合。
5. **兄弟站点**:sync.sh 会同步到 landing/whyiamright/context-os-theme/cchess,Phase 1 后需人工过一遍 4 个站点的首页截图。

## 5. 风险与注意

- **规范冲突**：本方案与 STYLE_BASELINE §2(1-3 条）直接冲突，采纳后必须先修订基准文件再动令牌，避免"实现与规范两张皮"。
- **品牌惯性**：现行 Monochrome Ink 刚在全站统一（2026-07-13 落地)，频繁换方向有工程成本；建议 Phase 1 先在小范围（App 内）验证观感再同步兄弟站点。
- **暖底与既有截图/OG 图**:`opengraph-image.tsx`、品牌物料是冷白底，需一并评估。
- **暖灰文字在纯灰 UI 上的外溢**:dashboard 卡片保持纯白（`--card` 不动），暖底只在大背景，避免"发黄"观感。
- **对比度复测是硬门**:§2 标注的近似值任何一项实测不达标，优先降饱和度保对比度。
