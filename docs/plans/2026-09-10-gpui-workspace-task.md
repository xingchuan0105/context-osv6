# GPUI D3 知识路径

D2 Windows 自动验收已通过。本批接通工作区、资料、问答引用和笔记，保留个人聊天及本机服务的已验收行为。

## 实施顺序与验证门

1. 复用 contracts/web-sdk/desktop-core：工作区列表与创建、资料上传和处理状态、笔记增删改、工作区会话与 RAG 请求。所有异步结果带对象/请求归属，切换工作区不串资料或草稿。
2. 原生视图：可辨识的个人聊天/工作区导航、总览、工作区上下文顶栏、默认收起的资料/笔记、直接选文件、引用原文；空数据、失败、重试和未保存笔记离开确认。
3. 自动验收：共享 Tauri 套件、GPUI TestPlatform 的真实视图与 Host/隔离 HTTP，覆盖创建、上传完成/失败、资料轮询、工作区问答范围、笔记保存/失败、导航与草稿、引用和窄窗口布局。
4. Windows 增量 check/build，更新关系图、验收记录和对等清单，仅提交本批文件。任一门失败先修复，不以夹具通过冒充真实入库/模型回答或三平台验收。

不使用 Computer Use、不要求逐项人工点验、不调用付费模型、不重启现有后端、不替换正在运行的客户端。用户在收到 35–50 分钟耗时说明后回复“开始验证”，本批按该授权执行。

## 当前进展

首轮工作区导航、创建、资料上传/处理状态/删除/重试、问答范围、历史引用原文、笔记保存/删除和离开保护已写入源仓库。`workspace.rs` 负责已有 API 的编排，`knowledge_view.rs` 负责状态和异步归属，`knowledge_render.rs` 负责视图；本机上传复用 `desktop-core` 的签名 URL 安全边界。

本批新增 8 条 GPUI 无头旅程及 1 条个人/工作区请求边界测试。52 项共享核心/聊天/HTTP 与 17 项无头 UI 合计 69 项通过；Windows UI check 和独立程序构建通过。首轮无头失败来自测试没有推进 GPUI 虚拟轮询时钟，已修正；同时修复迟到刷新覆盖刚保存笔记的竞态并验证跨工作区迟到结果被丢弃。完整命令、首次失败、复验与产物身份见 [验收记录](../desktop/2026-09-10-gpui-workspace-acceptance.md)。

D3 的原生视图/Host 自动门通过；真实文档入库与 RAG 模型链路、其余 Tauri 知识能力和三平台对等仍待验证或实现，不以本批结果宣布 D3 全部完成。当前运行的旧客户端和 18082 API 保持不变，新程序以独立文件交付。

## D3.2 前置门：Windows Office 解析包

只读检查发现已安装 `anydoc-lite` 只支持 DOCX/CSV，Excel/PPT 路由仍指向它；当前独立 API 没有 worker/嵌入配置。先替换不完整的解析器，使用后端已有 `anydoc-extract` 和固定版本的 `firecrawl-anydoc` Windows wheel，校验 SHA256，保留嵌入式 Python 隔离。

用户在 15–25 分钟说明后授权自动验证。9 项解析与 73 项共享/无头回归通过，资源映射及缺件拦截通过，独立 Windows 程序构建通过；[本门证据](../desktop/2026-09-10-gpui-office-parser-acceptance.md)。该门不调用模型，不以解析通过等同于真实入库和 RAG；后续独立栈和模型验证另行说明耗时及费用后执行。
