# VGI-RAG 高难度测试集：现成基准调研与设计

日期：2026-09-10。状态：调研与方案提案；尚未下载全量语料、冻结题目或启动在线评测。

## 1. 结论

最适合作为主基准的是 **BrowseComp-Plus**；检索层另用 **BRIGHT** 建立难度标尺；用 **FreshStack** 的信息点覆盖方法与 **QASPER** 的文内证据补足完整性、树导航评测。2026 年的 **EnterpriseRAG-Bench** 更贴近企业文件仓库，但其合成语料与规模应单独评估。

目标是找到普通检索存在明显提升空间、证据充分且能稳定评分的任务。难度按任务机制和开发集基线确定，不按 VGI-RAG 是否获胜选题。当前 VGI-RAG 同样可能低分：相似图并不自动提供实体连接、因果关系或冲突裁决能力。

文中外部数字均为作者发布结果或公开榜单快照，未在本机复现；不能直接作为 Qwen3.8 Flash 或当前在线 embedding 的预期成绩。

## 2. 现成测试集选型

| 基准 | 已核实的数据与任务 | 对 VGI-RAG 的用途 | 采用建议 |
|---|---|---|---|
| [BrowseComp-Plus](https://github.com/texttron/BrowseComp-Plus)（2025；仓库标注 ACL 2026） | 830 题，固定约 10 万文档，提供答案与相关文档标注；支持自定义检索器 | 多约束定位、迭代搜索、跨文档证据搜集 | 主基准；保持完整固定语料，抽题不缩语料 |
| [BRIGHT](https://github.com/xlang-ai/BRIGHT)（ICLR 2025） | 12 个领域，约 1.4k 推理检索问题；有短文和长文设置 | 隐含概念、表达差异、查询与证据的弱表面相关 | 单独的检索轨；不把 nDCG 当答案正确率 |
| [FreshStack](https://github.com/fresh-stack/freshstack)（NeurIPS 2025） | 5 个技术领域；社区问题、代码与文档片段、问题到信息点及信息点到证据标注 | 多观点覆盖、互补证据、版本相关技术问题 | 优先借鉴评分与构建方法；技术语料不能代表所有办公文档 |
| [MultiHop-RAG](https://github.com/yixuantt/MultiHop-RAG)（COLM 2024） | 2,556 题，609 篇新闻；推断、比较、时间及无答案题 | 跨文档检索适配与低规模技术验证 | 最容易先接通；是否足够难需新基线实测 |
| [QASPER](https://arxiv.org/abs/2105.03011)（NAACL 2021） | 1,585 篇论文、5,049 个问题；人工答案与证据 | 标题、章节、相隔较远的证据段落及限定文档问答 | 结构诊断补集；单篇模式不能证明跨文档图有效 |
| [QAMPARI](https://github.com/samsam3232/qampari)（GEM 2023） | 多答案实体列表，dev/test 各 1,000 题；证据分散于多个段落 | 枚举、交集、完整性、过早停止 | 第二批补集；实体别名和缺失金标须复核 |
| [EnterpriseRAG-Bench](https://github.com/onyx-dot-app/EnterpriseRAG-Bench)（2026） | 超过 50 万份合成企业材料，500 题、9 类来源；另有 100 道元数据题，不计入主榜 | 项目汇总、长文推理、冲突、遗漏、元数据 | 产品场景扩展基准；不能称真实企业原始数据 |

BRIGHT 的项目页与论文存在约一题的总数差异；正式接入以固定数据 revision 和实际可评题目清单为准。FreshStack 的论文、仓库快照也不能混作同一版本成绩。

### 2.1 哪些确实能让普通检索低分

以下是已发布的证据，不是对当前系统的预测：

| 来源与设置 | 作者发布结果 | 如何解释 |
|---|---|---|
| [BrowseComp-Plus 论文表 2](https://arxiv.org/html/2508.06600v1#S4.T2)：原始完整问题直接检索 | 证据 Recall@5：BM25 1.2%，Qwen3-Embedding-8B 14.5% | 单次检索很难找齐证据；不是问答准确率 |
| 同论文表 1、§4.8.1：固定 gpt-4.1 | Agent＋BM25 答案准确率 14.58%；Agent＋Qwen3-Embedding-8B 35.42%；直接给标注证据 93.49% | 大量失败可以来自找证据，而非读懂给定证据；普通向量也能明显帮助 Agent |
| [BRIGHT 官方榜单](https://brightbenchmark.github.io/)：2024 年原始直接检索行 | 平均 nDCG@10：BM25 14.5，text-embedding-3-large 17.9 | 有力的历史难度证据，不能当作 2026 年最强基线 |
| [FreshStack 仓库 2025-06-12 快照](https://github.com/fresh-stack/freshstack#freshstack-leaderboard) | 平均 Coverage@20：BM25 44.8%，四模型 Fusion 66.9%，Qwen3-8B embedding 68.9% | 覆盖仍有空间，但不能宣称混合检索已接近零分 |

截至本次访问，BRIGHT 官方榜单还列出了 2026 年 Mira 66.9、NeMo Agentic Retrieval 50.9 等 nDCG@10 成绩，系统配置不同。[NVIDIA 的公开实现](https://github.com/NVIDIA/NeMo-Retriever/blob/main/retrieval-bench/submissions/bright_agentic.md)结合了训练过的推理 embedding 与 Agent。不能拿旧 embedding 的分数与完整 VGI-RAG 直接比较来归因图和树。

BrowseComp-Plus 上述实验没有给出同设置下“BM25＋dense＋reranker”的成绩。本次尚不能证明强混合检索也会很低；必须加入本地公平对照。

### 2.2 近期方法与不宜直接混用的基准

[KARL / KARLBench（2026）](https://arxiv.org/html/2603.05218v1)将多种检索行为分开评估，包括定位、综合、数值推理和穷举；采用预先固定的信息点做完成度评价。其 Agent 的外部工具只有向量搜索，说明强 Agent 与普通向量索引的组合本身就是必要对照。该套件中的 PMBench 是内部数据；不能声称整套都可公开复现，也不能把其裁剪语料设置等同各来源的原始官方任务。

[FRAMES](https://huggingface.co/datasets/google/frames-benchmark)有 824 题、每题涉及 2–15 篇 Wikipedia 文章，含数值、时间、多约束等标签。问题与来源链接可用；本地固定仓库实验仍要明确文章快照、完整候选库与干扰材料，不能只导入每题相关页面。

[DeepSearchQA](https://arxiv.org/abs/2601.20975)有 900 个多步搜索任务，强调答案集合的完整性；适合借鉴任务和评分，原始开放网络环境不适合直接归因本地图或树。

[STaRK](https://stark.stanford.edu/)测试文本与显式关系结合的半结构知识库。它有助于研究关系检索，但现有 VGI 的 cosine 相似边没有这些事实关系；只给 VGI 组原始关系、其他组仅文本，会改变输入信息条件。

[MuSiQue](https://aclanthology.org/2022.tacl-1.31/)专门处理多跳题的捷径问题，可用于后续桥接任务设计。采用时要标明提供候选段落模式还是全语料模式，不能混用成绩。

## 3. 当前原型的适配边界

本次核对独立原型 `C:/Users/xingc/Documents/Codex/repository-tree/README.md` 与 `decisions/semantic-graph-v1.md`：

- 当前混合检索是关键词子串＋在线 dense cosine＋RRF，**不是 BM25＋dense**。新实验不得把它标成行业强混合基线。
- 文内是标题、段落、序号及前后块；图是章节窗口的向量近邻，无事实关系抽取。
- 原型导入保护上限 100 文档；图保护上限 4096 节点，超过后停止连边。直接搜索仍可能工作，因此必须检测图就绪度，不能将退化状态记作完整 VGI。
- 当前精确构图为二次复杂度。609 篇新闻也超过文档保护上限；10 万文档与约 5 万技术片段更不是修改常量即可承诺的容量。

采用公开大语料前，需要单独完成批量导入、可中断恢复、在线向量缓存、检索容量和图构建性能验证。Windows 原生和在线 embedding 的已确认选择继续保留；本轮不安装本地模型。

原始片段基准若没有标题或顺序，就按实际信息索引。不得由金标补出章节、目录或图边。能追溯到原始文件的片段可以使用来源固有结构，但必须记录映射、版本并给所有组相同正文和元数据访问权。

## 4. 建议的首版题集

### 4.1 三条评测轨分别报告

1. **公共检索轨：BRIGHT。** 优先选择非代码领域，按官方排名标注计算 nDCG@10、Recall@k；保持问题、排除 ID 和语料版本。选若干领域的结果明确标为领域子集，不与全榜平均直接比较。
2. **VGI-RAG-Hard-60 问答轨。** 下表为 60 道题的选题配额提案，20 道开发、40 道封闭测试。不是已选定的题目或已验证难度。
3. **回归轨：现有 20/128 题。** 保留已有答案和历史评分；后续只用于识别普通任务退步，不与新题混合成总分。

| 问答轨来源 / 主机制 | dev | test | 目的 |
|---|---:|---:|---|
| BrowseComp-Plus：多约束与迭代取证 | 8 | 12 | 主检索难度；完整固定候选语料 |
| FreshStack：互补信息点 | 4 | 8 | 验证答案所需内容的覆盖；先选一个领域 |
| QASPER：相距较远的文内证据 | 4 | 8 | 验证章节定位与全文局部阅读 |
| 自建跨文档桥接题 | 2 | 6 | 第一跳揭示第二跳线索；测试图是否带来新证据 |
| 自建版本／例外／否定题 | 1 | 3 | 相似内容中的关键差异与约束 |
| 自建边界与控制题 | 1 | 3 | 续读、限定范围无答案、简单定位回归 |
| 合计 | 20 | 40 | 来源与机制分层报告；小类别不作显著性结论 |

自建题优先使用授权的独立文档或明确标记的合成文档；题目与评分均不进入产品索引。所有自建题需人工核实答案、证据与备选合理回答。本次仅定义配额与机制，未生成或审定具体题目。

首次技术试跑可只用开发集 20 题；不能据此给出架构胜负结论。MultiHop-RAG 可先作为 609 文档适配验证；它不是上述高难度主基准的替代。EnterpriseRAG-Bench 与 QAMPARI 放在容量和基本方法稳定后的第二批。

### 4.2 六类难度机制

| 机制 | 题目需要的能力 | 预期暴露的问题（待验证） |
|---|---|---|
| 隐含概念 | 从问题情境推导检索概念，来源没有相同问法 | 原始 query 与证据的关键词和向量相似度都弱 |
| 多跳桥接 | A 文档提供代号／事件／关联对象，再到 B、C 核实 | 一次全局 top-k 召回不足；cosine 图也可能跨不过去 |
| 互补证据 | 多篇来源各支撑不同必要信息点 | 相似结果重复占满候选，少数观点被遗漏 |
| 跨节与续读 | 原文列表或条件跨块，定义与例外分处不同章节 | 只读命中块导致少一项或错用限定条件 |
| 相似干扰与版本 | 同主题、近重复、时间／范围／否定条件不同 | 图的主题扩散可能增加错误版本干扰 |
| 范围与控制 | 区分范围内无答案、需澄清和简单精确定位 | 不把额外绕路、误拒答或越界视作进步 |

为桥接题画出的金标证据依赖图只供评估使用，不能提供给检索器。取证路径可以有多种，不能要求 Agent 必须沿作者指定的那一条路径。

续读诊断应在预先固定的切块方案上评估，并保留少量不同合理块大小的敏感性检查。不得看过某组结果后专门移动边界让它漏证据。

### 4.3 冻结与难度验收

- 先按机制、证据质量、领域抽题；不查看 VGI 成绩选题。开发集可据强基线诊断筛掉已饱和或不可解的题，测试集不参与调参。
- 公共 benchmark 固定 dataset revision、源码 commit、文档 ID、正文 hash、语言、切块／原文映射、候选库大小、问题清单及评分版本。
- 能按同一事件、项目、文档家族分割时，按家族划分 dev/test。同一语料库可共享，但共享支持文档和相关题簇须报告；不能把随机问题拆分称为文档隔离。
- 保留原文语言。自动翻译后的题和语料另立派生版本，避免翻译改变 BM25 难度而混入官方成绩。
- 抽少量问题仍使用完整相关基准语料。若确需缩库，按预先冻结规则保留真证据、经核验的近似干扰和背景材料，命名为派生挑战集；不得声称复现官方难度。
- 难度看“强平铺检索与给定充分证据的差距”。建议开发集诊断目标为：给定金标证据的语义正确性达到 90% 左右，而强一次混合检索仍有明显差距；这是选集诊断目标，不是已测结果或发布门槛。
- 若直接给充分证据仍普遍低分，应先检查题意、金标或回答模型。若平铺 Agent 也接近满分，该层应补新任务，而不是收紧字面判分。
- 不设“VGI 必须高于某分”作为题目入选条件；低于基线的 VGI 结果也是有效证据。

## 5. 对照设计

### 5.1 保留已确认四组

| 组 | 检索能力 | 结构树 | 跨文档相似图 |
|---|---|---|---|
| A 完整 VGI-RAG | 相同混合检索 | 有 | 有 |
| B 去图 | 相同混合检索，保留普通向量 | 有 | 无 |
| C 去树导航 | 相同混合检索 | 无派生树导航 | 有，图构建输入与 A 相同 |
| D 桌面基础 Agent | 真实 ripgrep＋文件清单＋读取 | 无派生树导航 | 无 |

消融树不删除原始标题、文件名和正文中固有的格式；去除的是新增导航结构与相关工具。树与图的比较应报告工具实际使用和新增证据，不能仅凭开关存在推断机制有效。

### 5.2 建议补一组与检索层基线

新增 **E：相同 Agent＋相同混合检索＋平铺读取，无树无图**。A/B/C/E 才构成图×树的 2×2 对照；D 继续衡量桌面 grep 工作流。没有 E，A 对 D 的差距会混入向量检索的作用。

该组为新方案建议，不改变旧四组实验，也不在本轮执行。正式运行可分批，保持已确认的每路并发 2、总并发不超过 8。

检索层另行计算：BM25、dense、BM25＋dense（RRF）和加入 reranker 的强基线。一次检索结果与 Agent 多次检索分别报告。对于 A/B/C/E，使用完全一致的检索器；若升级成真正的 BM25＋dense，四组一并升级并冻结新版本，不能只给某一组改进。

相同 Agent 模型、版本、推理设置、上下文管理、返回正文容量、超时与重试。延续不设总 token 预算的选择，同时记录实际消耗及质量随搜索次数／读取量变化的曲线。参数遵循 embedding 服务的官方查询／文档编码要求，不让模型输入方式错误制造弱基线。

## 6. 评分与归因

遵循仓库 [RAG Eval v2](../../avrag-rs/docs/e2e-gates.md) 的语义评判方向，保留 correctness、faithfulness 等维度。官方 benchmark 原始指标与本地诊断指标同时保存；本地适配不宣称是原生产品 E2E。

| 层 | 指标 | 判定边界 |
|---|---|---|
| 检索 | nDCG、Recall@k；官方有则使用 alpha-nDCG、Coverage | 命中文档不等于读到了支撑段落；未知相关性不能自动当作错误证据 |
| 实际取证 | 已读正文支持的必要信息点覆盖、至少一套充分证据是否齐备 | 同一观点的多个替代来源属于 OR，跨文档联合证据属于 AND；不要求读齐全部重复来源 |
| 回答 | 语义正确性、必要信息点完成度、faithfulness；枚举题集合 Precision/Recall/F1 | 允许改写、合并解释和等价答案；关键事实、数值、范围错误仍计错 |
| 引用 | 引用支撑程度、可定位性、覆盖 | 与答案分开；引用位置或空 ID 不能单独把正确答案置零 |
| 行为 | 正确回答、合理无答案、需要澄清、错误拒答、越界 | 无答案只在固定可验证范围下成立；澄清不自动等同拒答 |
| 代价 | tokens、在线请求、P50/P95 延迟、读取量、索引时间和体积 | 总消耗包含失败、重试、判分；索引成本与问答成本分列 |

必要信息点及权重在看答案前固定，默认等权。合理补充内容不变成额外必答点；错误补充若造成重要误导则影响 faithfulness／正确性。对于自建题，每个信息点保存可接受的替代证据集合、原文区间和语义判据，避免只认唯一措辞或唯一来源。

不能复用上一轮已降级的“逐点与引用全通过”作为主要任务成功率。裁判出现“理由说支持但布尔值否定”“支持但来源 ID 空”等自相矛盾时，标为待复核，不直接判回答失败。

评分校准包含：等义改写、合法引用移位、不同有效来源，以及真实的实体／数值／否定／范围错误对照。小批人工双审并记录分歧；另一个模型或独立模型会话只能称模型复核。正式题目重复运行，按问题／题簇做配对置信区间，不把重复回答当作独立新增题目。

机制诊断至少记录：

- 图／树实际调用率，以及工具返回后是否读取了正文。
- 图带来的新证据中，有多少补足此前缺失的必要信息点；不能仅以新文档数当收益。
- 第一跳找到而第二跳缺失、读到足够证据但回答漏项、干扰版本误用等失败类型。
- 在同一冻结图上做离线可达性检查：金标证据之间是否存在合理短路径、是否被窗口平均稀释；只供诊断，不将金标反哺测试图。
- 对 A/B 的配对失败审查区分“没有可用边”“有边但 Agent 没用”“用了却没读”“读了未整合”。

## 7. 可复用组件与数据边界

| 可复用项 | 用途 | 范围与注意点 |
|---|---|---|
| BrowseComp-Plus 的自定义 retriever、qrels 与评测接口 | 接入相同 Agent 的多种检索器，输出排名与轨迹 | [官方仓库](https://github.com/texttron/BrowseComp-Plus)；代码 MIT，[语料卡](https://huggingface.co/datasets/Tevatron/browsecomp-plus-corpus)标 MIT；问题与答案独立于产品语料保存 |

接口适配优先复用数据和指标，不为研究基准安装整套 GPU 训练栈。许可标签是本次页面核对记录；打包分发时仍需保留具体下载版本的声明与来源文件。

评测数据分为三个不可混写的空间：产品可见原文与固有元数据、派生索引、评估专用问题／答案／证据依赖及评分。问题、金标、人工证据图、干扰标签、题型和历史回答均不得写入 Agent 可读取的 corpus、目录名、固定产品提示或归档规则。当前问题只作为当次 Agent 的用户输入，其余题目与金标由评估器隔离。

## 8. 开始实测前的交付门槛

1. 固定主语料与选题 manifest，人工核实开发集；保留官方完整候选库或明确标派生设置。
2. 验证容量和图就绪，建立真正 BM25＋dense 的强基线；在小规模数据上核对 ID、原文和标注映射。
3. 完成 20 道开发题技术试跑，校准评分并确认是检索瓶颈；参数随即冻结。
4. 封闭测试集配对重复运行，报告分层质量、稳定性、成本和取证路径；不按结果删题。

本次交付止于调研与设计。具体问题清单、人工审定、容量改造、强基线实现和在线运行均未完成；没有新的 VGI-RAG 成绩或胜负结论。
