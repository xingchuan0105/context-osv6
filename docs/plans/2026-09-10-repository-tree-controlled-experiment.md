# 普通 Agent 与仓库树：典型 20 题对照实验方案

日期：2026-09-10。状态：**设计完成，实验接口待实现，尚未启动在线对照**。按用户最新要求，从现有 128 道纯 RAG 中选典型 20 题，四路各并发 2、总并发上限 8；沿用三次重复，共 240 个答案。本方案承接[原型评测](2026-09-10-repository-tree-rag128.md)，使用 Windows 原生、Qwen3.8 Flash、在线 embedding，不设 token 预算上限。独立工程为 `C:\Users\xingc\Documents\Codex\repository-tree`。

## 1. 普通 Agent 怎样检索

普通检索 Agent 的核心是模型在工具循环中自主决定：形成查询、查找候选、打开原文、发现遗漏、换词或缩小范围再查、合成带来源的答案。它可以使用向量库，也可以使用文件搜索；多轮工具调用本身不要求仓库树。[ReAct 原论文](https://arxiv.org/abs/2210.03629)描述了推理与环境行动交替的机制，[LangChain 官方 Agent 文档](https://docs.langchain.com/oss/python/langchain/agents)也以模型调用工具的循环定义 Agent。

本实验采用两种可复现的普通 Agent 基线，不声称覆盖所有商业 Agent：

| 基线 | 典型过程 | 已具备的能力 |
|---|---|---|
| 平铺混合检索 Agent | 列文档 → 向量/关键词搜索 → 读取命中及相邻内容 → 补检 → 回答 | 语义改写、多轮搜索、按文档缩小范围、连续阅读 |
| 文件检索 Agent | 列文件 → grep 关键词/正则 → 打开命中附近文本 → 换词/扩大阅读 → 回答 | 文件名定位、精确术语搜索、连续阅读、多轮策略 |

例如，正文有四个观点，首次命中只含前三个：普通 Agent 已经可以继续读取下一段。树导航的额外能力是直接定位父章节、兄弟章节及其范围，帮助判断还有哪些部分可能遗漏。不能把“允许 read”只给树组，否则测到的主要是阅读权限差异。

“一次检索 top-k 后生成答案”作为传统 RAG 的辅助参照，不作为普通 Agent 的唯一代表。

## 2. 要回答的问题与现有证据边界

主问题：**在相同模型、材料与连续阅读能力下，显式目录/章节树是否提高答案质量或降低完成任务的成本？** 次问题：普通文件 Agent 增加向量混合搜索后有多少收益，树的作用是否依赖向量能力？

现有 `qwen38-first-pass` 是 10 份文档、872 块、128 道题的一次完整运行。原型使用 Python 字面子串与向量 RRF，尚未调用 ripgrep，也未实现跨文档语义聚类或 SVD。113 道应检索且带 gold 的题中，90 道全部 gold 片段可在单个实际已观察块匹配；125/128 个答案的 correctness 被裁判评为 1.0。前者说明证据较局部，后者说明评分有满分聚集，两者都不能证明所有题简单。

历史完整 SaC 的模型、裁判、接口和部分题库不同。它保留为历史成绩参照，不能代替任何本轮对照组。所有新组使用同一份当前题库中固定的 20 题，不必排除历史比较中变更过的题；119 题口径只适用于旧运行之间的比较。当前 20 题是机制覆盖的目的性选样，不是随机抽样，不能用其均值估算全 128 题的成绩。

本轮“树”限定为当前可构建的**目录层级＋文档标题层级及块范围**，两者作为一个能力包测量。它不包括 LLM 摘要、知识实体图谱、聚类树或 SVD；也不能分别归因于目录和标题，拆分它们需要后续消融。

## 3. 四个主实验组：2×2 设计

| ID | 定位 | 真正的 grep | 向量混合搜索 | 连续读取、平铺文档清单 | 显式目录/章节导航 |
|---|---|---|---|---|---|
| A：hybrid-flat | 普通混合检索 Agent | 有 | 有 | 有 | 无 |
| B：hybrid-tree | 混合检索＋仓库树 | 有 | 有，与 A 相同 | 有，与 A 相同 | 有 |
| C：grep-flat | 普通文件检索 Agent | 有 | 无 | 有 | 无 |
| D：grep-tree | 文件检索＋仓库树 | 有，与 C 相同 | 无 | 有，与 C 相同 | 有，与 B 相同 |

所有主组都由同一个模型自主决定调用顺序及何时作答，允许查询改写、重试、缩小文档范围、连续阅读。树组可以完全不使用树，不强制先浏览目录。

预先固定比较：

- **B−A：有向量能力时，额外提供显式树导航的增量。** 这是最直接的主比较。
- **D−C：没有向量能力时，额外提供显式树导航的增量。** 检验树是否只在某种检索条件下有效。
- A−C、B−D：增加向量混合搜索工具的增量，作为次要比较；包括模型因新增工具而改变策略的影响，不等于 embedding 排序算法单独的效果。
- `(B−A)−(D−C)`：探索树与向量能力之间的交互，避免只凭某一组最高分下结论。

平铺组保留文件名、原路径、类型、时间字段、原文标题、块序号及前后位置。模型自行读出目录或标题关系是正常能力。A/B 使用完全相同的、已含标题路径的文档向量。因此本轮测的是**额外提供可调用的层级索引的价值**，不是“删除所有结构信息”的效果。

## 4. 工具和数据契约

以下是拟实现的实验接口，不表示现有运行器已支持这些工具；实现时不新建第二套 Agent 框架。

| 工具 | 可用组 | 契约 |
|---|---|---|
| `list_documents(cursor?, limit=50)` | A/B/C/D | 平铺清单，含稳定文档 ID、名称、原相对路径、类型、可用时间、总块数；分页，不提供合成摘要 |
| `grep(pattern, match=literal\|regex, document_ids?, limit=15, cursor?)` | A/B/C/D | 本机真实 ripgrep；定位结果映射回相同文档、块序号及来源位置；支持翻页 |
| `read(document_id, seq, count=4)` | A/B/C/D | 一次 1–32 个连续块；含原文、标题路径、prev/next/total、来源哈希、稳定定位与本轮短引用 ID |
| `hybrid_search(query, document_ids?, limit=15)` | A/B | 同一个 grep 字面匹配通道＋在线 query embedding＋缓存文档向量余弦排序，固定 RRF 参数；上限 30 块 |
| `tree_children(parent_id?, cursor?, limit=50)` | B/D | 目录或文档节点的直接子节点；只暴露当前 scope 内节点和计数，返回稳定节点 ID |
| `outline(document_id, cursor?, limit=50)` | B/D | 同一份解析结果的章节树，含父子关系、起止 seq；长目录分页，不生成 LLM 摘要 |

文件夹节点可返回作用域内的后代文档 ID 集合，供共有的搜索过滤使用；集合超限时分页。Agent 传入的文档范围始终与题目允许范围取交集，空范围不扩大为全仓。文件列表中的元数据不计作正文已读；搜索/阅读真正返回的正文才进入已观察证据账本。

### 4.1 真正的 ripgrep 和公平性

`grep` 执行固定版本 Windows `rg.exe`，以参数数组调用并解析机器输出；在预先冻结的、同一解析器产生的 UTF-8 正文上搜索，不能拿另一种 PDF/DOCX 转换器的输出作对照。字面与正则模式分开，大小写规则固定；[ripgrep 官方指南](https://github.com/BurntSushi/ripgrep/blob/master/GUIDE.md)区分了默认正则与固定字符串搜索。

搜索用解析后的整篇正文，不因 embedding chunk 边界把一个连续词串切断。命中位置映射至对应块；跨块命中保留覆盖范围。对所有组统一去重、排序、截取和错误协议：grep 按冻结的文档顺序及正文位置排序，混合检索对该字面结果与向量结果作 RRF。具体候选池大小、RRF 常数和并列处理在运行前冻结，不按本批答案调整。

返回默认 15、最多 30 个结果只是单次工具页面大小，不是 token 上限；模型可以翻页、换词、再读。源路径与正文中的标题不遮蔽，但不把自动生成的目录说明或树摘要混入平铺组搜索正文。

### 4.2 所有组共同修复的接口问题

旧批次有 38 次工具错误、18 题包含无效引用 ID。本实验冻结前统一完成：实际 schema 与描述一致；错误包含可识别原因；短引用如 `E17` 由宿主映射到不可变的文档 ID、seq、source hash 和位置。相同正文在同一题内复用短 ID，其他题或组的 ID 不可引用。

引用只能绑定本次真实返回给 Agent 的文本。文档清单或目录提到某章节，不等于该章节正文已经读过。所有组相同地使用短引用与验证器，不给树组专属引用修复。旧答案、旧引用及旧分数保持原样，新实验全部重跑。

工具限制衡量的是“同一运行环境下开放不同能力”的效果；树调用也占工具次数。如果触顶影响结果，报告受影响的题，不能只给某一组扩大上限。更高上限属于四组统一配置的新批次。

一个题目槽位覆盖生成、原生裁判及实验裁判的完整流程，裁判顺序执行，不另起每路两个后台裁判。Agent、裁判和 embedding 对外请求共同受全局 8 请求槽控制，避免工具批量调用或重试突破并发上限。429、排队和退避时间计入成本/延迟；限流时统一调度，不能只降某组并发后仍称同配置。路末收尾或服务退避时实际并发可以低于 8。

资料与索引是 Agent 的可访问输入，参考答案、gold、期望行为及逐点 rubric 只对评测器可见。模型返回的实际 model ID、usage 与服务端限制要记录；不能失败后切到别的模型，再并入同一组。

## 6. 评分：保留 E2E 口径，增加能区分高分答案的指标

### 6.1 两套评分分别保存

1. **原生桥接口径**：保持当前 Eval v2 correctness、faithfulness、relevancy、refusal 和核心标签的规则，保留其适用题分母；用于与既有报告衔接。
2. **实验主口径**：运行前冻结一份独立逐题 rubric，列出必要回答点、关键例外、允许的回答行为和来源锚点。旧题库不改写，差异另表说明；该 rubric 不根据新组输出修订。

必要回答点由题意和权威原文确定，不以已有 Agent 答案为标准。裁判输入保留原有 `expected_should_answer` 和 `rubric_notes`，同时明确两套口径的差异。对有争议的拒答/澄清标签，事先人工核对，不能看到哪组占优后再决定标准。

实验行为分为 `answer`、`clarify_scope`、`correct_premise`、`insufficient_evidence`。允许合理组合，例如先纠正题干，再根据原文回答。每题预设可接受行为集合及判断依据，避免一个 `is_refusal` 布尔值把正常澄清或纠错都判错。

### 6.2 主指标与诊断指标

| 层次 | 指标 | 计算或解释 |
|---|---|---|
| 主指标 | 有来源支持的必要点覆盖率 | 每道需要实质回答的题，已正确回答且被本次已观察材料支持的必要点数 / 冻结必要点数；先按题算，再宏平均 |
| 主护栏 | 重大无依据断言率 | 答案含至少一个影响结论、条件或数值的无依据断言的题占比；答案越长不应靠分母扩大获益 |
| 行为 | 回答/澄清/纠错/证据不足的决策正确率 | 固定 20 题按独立行为 rubric；另报各行为类型的分母 |
| 严格交付 | 任务成功率 | 行为正确、所有必要点得到支持、无重大错误、关键事实引用可解析且语义支持；单独标注，不命名为原生 PASS |
| 引用 | ID 解析率、语义支持率、关键事实引用覆盖率 | 分开衡量引用能否定位、是否真正支持对应句、应引用的事实是否引用；不拿 gold 匹配率代替事实支持 |
| 检索 | 全部已观察块召回、前 15 个唯一已观察块召回、首次 search 召回 | 沿用冻结逐块 gold 匹配规则；有 gold 且应检索题才适用；跨块窗口只作补充，不混入主口径 |
| 效率 | Agent 总 tokens、输入/输出/缓存明细、LLM 请求、工具次数、embedding 请求 | Agent 与裁判分别计量；embedding 单列；未知 usage 不填零 |
| 延迟 | Agent 端到端中位数/P95、检索/阅读耗时、首个有效证据耗时 | 不含 judge；失败和超时另报，成功题耗时不能掩盖失败率 |
| 建索引 | 解析/结构索引耗时、embedding 时间与费用、磁盘占用 | 与在线答题分开；本批只复用缓存时不伪称重新测过建库性能 |
| 稳定性 | 工具错误、无效引用、触顶、基础设施失败、裁判失败 | 总题数固定；不剔除失败后只报告成功案例 |

“有来源支持”需要同时满足答案确实表达了要点、材料确实支持它，不能仅因工具返回过包含答案的段落就给覆盖分。可联合本题本组真正观察到的多份来源；不能拼接另一组或另一轮的证据。必要时使用权威原文核验事实真伪，但权威原文不能冒充 Agent 已观察材料。

只需澄清且没有事实性必要点的题，必要点覆盖标 NA，纳入行为正确率。报告所有指标的实际适用题数及公共配对子集；一次重复中的生成系统失败按覆盖 0、任务失败计，裁判缺失则标未完成并补判，不擅自当质量 0。部分观察失败也保留原始轨迹。

### 6.3 盲评与人工复核

裁判一次只看一个匿名答案、该答案自己的已观察正文/引用映射，以及冻结 rubric；不看组名、工具名、成本、另一组答案或另一组证据。引用先转成统一局部标识。材料中的来源信息保留，不能为了盲化丢掉判据。

实验前固定六个诊断审查 qid：22、79、90、104、108、134，分别覆盖完整列举、表格统计、PDF 时间表、全仓综合、空范围澄清和历史指代。对其四组、三个重复共 72 个答案做人工盲审，核验逐点覆盖、事实支持和行为判断。这是目的性覆盖审查，不能用其错误率估计所有题的裁判错误率。再单独复核其他题中的重大分歧、引用异常与行为争议，记录额外复核原因。

若发现评分器系统性缺陷，先固定修订及原因，再用所有组原答案统一重判，保留旧分数。不能只重判不喜欢的答案。单模型裁判与人工抽样仍有局限，结果中明确披露。

## 7. 样本量、执行顺序与统计

主实验为 **4 组 × 20 题 × 3 次独立重复 = 240 个答案**，每组 60 个答案。三次重复估计随机波动，但不同问题只有 20 道，不能当作每组 60 道独立新题。题集和重复次数对四组完全相同。

每个 qid×重复构成一个四组配对区组。每次重复使用预先保存的共同随机题序，四路同时启动、各自以两个槽位推进；本次重复的四路完成后再启动下一次重复。技术小批固定为第一次重复的前两题 22、80，其余题按固定种子乱序；第二、三次重复全题乱序。保存实际开始/结束时间与供应商返回模型；模型服务不支持生成 seed 时不声称固定了模型随机性。不同路进度可以不同，不能拿四路总墙钟时间代替逐题耗时。

主估计：先对每题每组的三次重复取均值，再计算配对差。对 qid 做 10,000 次成簇配对 bootstrap，保留该题全部组别和重复，报告点估计与 95% 区间。只预设两个树增量主比较 B−A、D−C；若作显著性判断，对这两个比较使用各自 97.5% 区间控制家族误差，其余为探索性分析。

这些区间只描述固定十份文档、当前目的性挑选的二十题内的重采样波动，不包含选题偏差、新文档、新领域或供应商版本变化的不确定性。多题共用同一来源，不能把它们解释成全 128 题或任意文档总体的置信保证。

分层预先登记：单文档/全仓/空 scope、格式、是否跨文档、是否完整列举/例外、原生题型。类别可重叠，不能加总成 20。很多题型仅一题，只描述案例和三次重复稳定性，不以单题均分宣布整类题型胜负。

主要报告质量与 tokens/延迟的共同变化，不把不同花费区间事后截出来称为“同成本因果对照”；也不截断已完成轨迹模拟低预算运行。无 token 上限是本轮约束，实际成本照实报告。

质量无显著差异不等于等效。工程判断参考值为覆盖提升 3 个百分点，或在覆盖下降不超过 1 个百分点、无依据断言不增加的前提下，tokens/延迟下降 15%；这是本设计的决策参考，不是已有用户验收线。若区间不能支持相应改善/非劣界限，结论为证据不足，不能以均值接近宣告相同质量。20 题只适合机制筛查，尤其不足以可靠证明很小的非劣界限。

## 8. 两个可选诊断组与后续压力集

### 8.1 多轮与阅读的贡献：主实验后再决定

| ID | 配置 | 比较目的 |
|---|---|---|
| S0：single-shot | 同一 query 的固定 hybrid top-15，随后模型生成答案，无后续工具；共用引用与评分 | 与 S1 比较一次检索和自主迭代策略 |
| S1：search-only | 同一 Agent、平铺清单、grep/hybrid，可多轮，无 read 与树 | 与 A 比较增加原文连续读取的效果 |

S1−S0 是整个自主搜索策略的增量，包含查询改写、搜索次数与文件定位，不能只归因于“多一轮”。A−S1 检验读取权限的增量；S1 是刻意受限的诊断组，不称为完整普通 Agent。

如执行两个诊断组的同一 20 题×3 次，额外 120 个答案；与主实验合计 360 个答案。两个可选组在主实验后单独运行，各并发 2、合计最多 4，不同时开启六路。主实验 A 可直接复用的前提是代码、模型、题库与共享配置完全未变。完整 SaC 的同模型重跑另作架构参照，不挤入四组树消融。

### 8.2 为什么典型 20 题之后可能仍需要扩题

当前语料只有 10 份文档，二十题适合先筛查“哪些任务可能依赖树”，不足以证明大型仓库的目录路由价值。若存在有意义的差异但区间太宽，可另行扩回完整 128 题；若仍有满分聚集，可另立未执行的压力集：跨块完整列举/末尾例外、同名多版本、时间条件与冲突、跨文档联合条件、未知目标文档、证据不足与错误前提，六类各 8 题，共 48 道新题。

压力集应先用独立来源形成答案与引用锚点，再冻结题目；加入干扰文档时避免意外改变正确答案。可以用 100 份文档测路由，另用更大文档集测本机索引与工具性能；不能把机械复制同一文件当成新的语义难度。扩回 128 题、新题和扩库都不属于本轮 20 题范围，已有失分题也不能作为新增题唯一来源。

## 9. 实施步骤、验证门与预期耗时

| 阶段 | 工作 | 进入下一阶段的条件 |
|---|---|---|
| G0 共用接口 | 真实 rg、正文位置映射、平铺清单、树接口、短引用、工具描述一致性、分组开关 | 四组只有登记的能力差异；禁止未开放工具的旁路访问；旧产物不变 |
| G1 本地协议验证 | 合成文档检查跨块第四点、范围限制、翻页、Unicode/CRLF 定位、正则与字面模式、引用只绑定已读正文 | 功能与隔离检查通过；不调用付费模型；版本和映射可冻结 |
| G2 评分与配置冻结 | 人工确认选定 20 题实验 rubric、冻结题库/源/索引/Prompt/模型配置、随机顺序和六题人工审查清单 | 每题可审查，gold 仅在评测器；变更有版本记录 |
| G3 技术小批 | 固定 q022、q080，每题四组第一次重复，共 8 个答案；四路各并发 2，实际检查总并发 8 | 只看协议、引用和产物完整性，不以质量分高低决定放行；原始低分保留 |
| G4 正式跑 | 配置未变则复用 8 个小批答案，续至 240，剩余 232；后台日志及用量账本 | 每路并发上限 2、总上限 8；全部组合有明确状态；原始失败、重试、触顶完整保留 |
| G5 分析与交付 | 盲评、人工审计、原生/实验口径双报、配对区间、成本与失败分布 | 可以逐条追溯结论；混杂或缺失项显式披露 |

公共接口和报告器的准备工作仍粗估 1–2 个开发日，不因减题自动消失；20 题 rubric 与 72 个答案人工审查另预留约半天。正式在线主批暂估 **30–90 分钟**：旧批次约 43 分钟、128 题、并发 2，按 240 个答案和总并发 8 理想线性折算约 20 分钟，再预留精选难题、双口径裁判、尾部和服务限流影响。以 8 个技术小批实测修正，不承诺四倍提速。可选诊断组另作单独时间估算。本设计不规定费用或 token 封顶。

新调度器按四路/独立子任务管理日志、静默 watchdog 和恢复点，总计划时限在小批后记录；旧批次的 120 分钟总 watchdog 不作为本批时长承诺或 token 上限。质量失败不触发停止。连续基础设施失败触发暂停调查，不切模型或挑题跳过；修复如改变公共实现，创建新 run-id 并四组统一重跑。

每条执行键是 `(experiment_id, arm, qid, repeat)`。重试保留所有尝试，协议失败可在相同配置恢复；有效答案不得因为低分重生成挑最好。裁判失败可以针对原答案重试。报告同时披露首次尝试与恢复情况，延迟和费用包含重试，不能只保留最快的成功尝试。

首次逻辑尝试内部的网络重试策略四组一致并预先冻结。主结果保留首次逻辑尝试的生成系统失败为 0/失败；恢复后成功的答案另列“恢复后结果”，不替换主分母中的原失败。裁判补判始终针对同一个原答案，不构成 Agent 重生成。

## 10. 交付物与结论模板

拟存储在独立工程 `.eval/controlled/<experiment_id>/`：`manifest.json`、来源与索引哈希、工具/Prompt 快照、匿名评分输入、逐题答案/轨迹、引用映射、原生与实验评分、随机运行顺序、usage/error 账本、人工审查记录。实验 rubric 置于评测私有目录，不进入产品 Skill 或公开索引。

报告输出组别总表、B−A 与 D−C 配对差及区间、质量与成本二维比较、预登记分层、工具和失败分布、典型分歧案例。案例都附答案句子和本题实际来源，不用只展示获胜案例的方式代替总体结果。

| 观察结果 | 可以作出的结论 |
|---|---|
| B、D 相对各自基线均有可靠质量增益 | 本语料和模型条件下，显式目录/章节导航有增量价值；尚不证明聚类/SVD |
| 质量保持且成本下降，区间支持非劣与降幅 | 树可降低该条件下的信息获取成本 |
| A≈B、C≈D，但 S1 或 A 优于更弱诊断组 | 高分更可能来自多轮搜索/原文读取；树额外收益尚未检出 |
| 点估计接近而区间宽，或大量满分 | 当前题库分辨力不足；不能宣告等效或树无效 |
| A、B 明显优于对应 grep 组 | 在线向量混合工具仍有价值，不能据此说业界可普遍放弃向量 |
| C/D 成绩接近且成本更低 | 该规模语料适合文件检索；需新仓库与新题验证外推 |
