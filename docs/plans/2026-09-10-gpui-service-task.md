# GPUI D2 本机服务

D1 基础聊天、阅读和标题已由用户验收。本批把现有 desktop-core 的本机服务能力接入 GPUI，保持独立工作区、现有协议和已验收的聊天路径。

## 实施与验证门

1. 服务面板：实际 API 地址与健康、PG/Redis 端口、后台任务进程、运行工具和日志目录；状态探测不在 UI 线程执行。端口可达与完整服务就绪分别标记。
2. 启动链：数据栈 → 产品迁移/API/worker → 本机会话，展示当前阶段和错误，允许重试；聊天草稿和历史状态保留。独立配置的 API 只连接，不隐式拉起另一套服务。
3. 退出链：只停止本次启动且进程记录仍匹配的组件，产品先停、数据服务后停；已有外部服务保留。启动与停止串行，关闭窗口等待清理结果，失败保持窗口与可恢复提示。
4. 复用共享 Tauri 测试、增加健康响应/实际端口/进程归属/生命周期顺序测试；Windows jobs=2 构建。自动化门通过后更新验收程序，由用户操作窗口。

用户已授权本批 25–40 分钟验证：隔离夹具和现有服务只读探测，不停止现有后端、不调用付费模型、不使用 Computer Use。真实冷启动、迁移与受管服务退出若尚未操作，保持待验，不用夹具测试替代 S2/S6 真机门。D3–D6 和 Tauri 发布保持现状。

## 本批交付

服务面板、分阶段连接、实际 API 健康检查及按本次进程归属清理已实现。45 项单测/隔离接口测试、1 项真实 API 只读探测和 Windows 构建通过，新版已打开。用户窗口复验与受管冷启动/退出门待验，详见 [D2 接线与验收](../desktop/2026-09-10-gpui-services.md)。
