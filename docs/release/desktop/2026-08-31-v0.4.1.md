# Context-OS Client v0.4.1

- **Date**: 2026-08-31
- **Product**: Context-OS Client (Windows x64 NSIS)
- **SemVer**: `0.4.1`（PATCH：修复 0.4.0 起新装/冷启动即坏的数据面）
- **Source of truth**: `desktop/package.json` + `desktop/src-tauri/tauri.conf.json` + `desktop/src-tauri/Cargo.toml`
- **Business model**: ADR-0010（免费客户端；云端分享名额 + 钱包；无激活闸）
- **Baseline**: trunk `8898b6b6`（2026-08-31）

## User-visible changes

1. **修复全新安装/全新数据冷启动失败**（0.4.0 首启即报「本机产品会话未就绪」）。根因：8 月租户隔离安全波的三项改动与桌面端未对齐——
   - 运行时角色守卫拒绝 superuser 连接，而桌面把 `avrag` 直接建成 initdb bootstrap superuser；
   - Windows 安装树没有任何迁移执行路径（`AVRAG_RUN_MIGRATIONS` 死键，迁移归 `avrag-migrate` 独占但从未打包）；
   - 强制 RLS 后 pgvector 检索面全部写入违反策略 / 读取静默空集（ingestion 卡 queued、搜索/导出为空）。
2. **修复存量数据升级后本机 API 起不来**：老数据树的 `avrag` bootstrap superuser 会被原地修复（新建 `avrag_cluster_admin`，运行时角色降权），无需重置数据。
3. **对齐 trunk**：本机侧配套（ingestion/搜索/分享导出在强制 RLS 下的租户上下文）随 `8898b6b6` 进入安装包；E2E `publish-share`（l3：登录 → 建库 → 上传 → publish 上云 → 外链分享 → 云端分享页 RAG）真机通过。
4. Sidecars（`avrag-api` / `avrag-worker` / `avrag-migrate`）自当前 trunk 重新交叉编译；新增 `avrag-migrate` 为第四个随壳分发的 sidecar，冷启动先迁移再起 API，迁移后自动补运行时 DML grants。

## Known issues

- Authenticode 未签 / 自签 → SmartScreen「未知发布者」提示，选**仍要运行**。minisign 更新签名不受影响。
- 更新下载期间不校验磁盘剩余空间（NSIS 安装器自身有基本检查）。
- 0.4.0 客户端可经「设置 → 关于 → 检查更新」自动升级到本版；≤0.3.1 无 updater 代码仍需手动下载。
