# 表格（Markdown 管道行）是什么

知识库文档里的表格，转成文本后常见形态是 **管道行**：

`| 列1 | 列2 | … | 列n |`

## 结构

- **一行 = 一条记录**：记录是各列合在一起的整体，不是「某一列单独算一个对象」。
- **表头（或首行）给列命名**：格子里的字只有贴在 **同一行 + 该列表头含义** 下，才是该属性的值。单独一个数字不完整；完整事实是「计量对象（表头/邻列）+ 该格」。
- **列由粗到细很常见**：左侧多为阶段/类型/分类；右侧更靠近编码、角色、状态。左侧相同、右侧不同的多行，是多条不同记录。
- **重复**：只有 **整行各列都相同** 才是重复行。某一列（例如名称）相同而其它列不同 → 多条记录。
- **`grep` 的 `total_hits`**：服务端统计的 **命中了多少行**。名称列是否重复，不改变这个数字的含义。
- **编码/活动号是标签**：如 `ROW-04` 是名字，不是排序键。「第一个」若指流程或表中的先后，对应 **表中出现顺序** 或显式序号列，不是标签字符串的字典序或数值最小。
- **类型词可能出现在多处**：阶段名既可在类型列，也可嵌在描述句里。单元格在文本里常呈两侧 `|` 夹住的字段（如 `| 验收 |`）。
- **`grep` 的 before/after（context）**：邻列与邻行文字；格子含义常分布在邻域里。

## 示例（虚构表）

### 1. 行计数

```text
问：状态为「在库」的货位有多少行？
回传：
  total_hits=12  （pattern 命中状态列「在库」）
  多行品名相同、库位不同
读出：在库 12 条记录。total_hits 即行数；品名重复不改变行数。
```

### 2. 表序

```text
问：角色 R 负责的第一个步骤是什么？
回传（表中出现顺序）：
  | … | R | STEP-03 | … |   ← 该角色下先出现
  | … | R | STEP-04 | … |
读出：第一个 = 表序在前的 STEP-03（步骤号不是排序键）。
```

### 3. 表头与单元格

```text
问：该规划有多少个 L2 配置项？
回传：
  | 层级 | 数量说明        |
  | L2   | 42个配置项（L2） |
  或邻行/邻列同时出现「配置项」「L2」与 42
读出：42 是 L2 配置项数量（表头/邻域给出的计量对象）。
```

## 误读对照（同一回传）

下列均用 **同一段虚构回传**：左栏是常见误读，右栏是与结构一致的读法。

### A. 标签当排序键

```text
回传（过滤角色 R 后的出现顺序）：
  | 阶段 | 角色 | 活动号   | 名称   |
  | 概念 | R    | ACT-04  | 立项准备 |
  | 概念 | R    | ACT-03  | 范围确认 |

误读：第一个 = ACT-03（把活动号当数值/字典序最小）
正确：第一个 = ACT-04（过滤结果里先出现的行；ACT-* 是标签）
```

### B. 列重复当去重计数

```text
回传：
  total_hits=8
  hits 中「品名」列多次出现「零件甲」，库位列不同

误读：只有 3 种品名 → 回答 3
正确：8 行记录（total_hits）；品名重复不合并行
```

### C. 样本长度当全量

```text
回传：
  total_hits=37
  truncated=true
  hits 仅 50 条上限内的前缀样本（本例展示 5 条）

误读：数 hits 得 5 → 回答 5
正确：计数用 total_hits=37；hits 只用于展示/抽字段，不是全库枚举
```

### D. 表头错绑数字

```text
回传：
  | 层级 | 说明              |
  | L1   | 12个顶层模块      |
  | L2   | 42个配置项（L2）  |

问：L2 配置项有多少？
误读：看到 12 更靠前 → 答 12
正确：L2 行 +「配置项」邻域 → 42
```
