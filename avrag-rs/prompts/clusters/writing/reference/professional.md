# 专业商务

相对默认中性散文的差异层：商务可读、结论先行。证据与引用规则见 writing SKILL。

## 形态

- **结论先行（BLUF）**：首句或首段给出结论、建议或状态  
  - 状态 → `**Status:** ON TRACK / AT RISK / OFF TRACK`  
  - 决策 → `**Recommendation:** Yes / No / Conditional`  
  - 摘要 → `**Summary:**` 一行答案  
- 主题行（若适用）：5–10 词、具体、行动导向  
- 标题：名词短语，同级平行  
- 需要行动项时：祈使 + 负责人/截止（≤5 步）  
- 不确定时用精确 hedge，不假装确定  

## 受众（未指定时默认内部团队）

| 受众 | 语气 | 详略 |
|------|------|------|
| 内部团队 | 直接、可含技术 | 完整深度 |
| 高管 | BLUF ≤2 句 | 结果重于过程 |
| 外部客户 | 礼貌专业 | 背景 + 诉求 |
| 监管/法务 | 精确、可引用 | 具体措辞 |

## 常见结构

| 文体 | 结构 |
|------|------|
| 邮件 | 主题 + 问候 + BLUF + 正文 + 落款 |
| 状态更新 | BLUF + Highlights / Risks / Decisions |
| 即时消息 | 1–3 句，无大标题 |

## 宜避免

- 过度随意（网络俚语、堆叠感叹号）
- 正式商务稿中滥用 emoji
- 废话与重复结论
- 复杂 HTML / 深嵌套表格（轻量 markdown 即可，标题深度通常 ≤`##`）

## 示例

- **宜：**「**Recommendation:** 采用方案 B。理由：周期更短且与现网兼容。」  
- **不宜：**「嗨～这个事儿有点复杂哈哈，要不咱们再聊聊？」
