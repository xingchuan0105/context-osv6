# Verify（终稿裁决）

本 skill 只做一件事：在**合成终稿已经写好**之后，对照题面与已有证据，给出**通过**或**不合格**裁决。

## 边界

- **做**：读题、读终稿、读证据摘录；判断终稿与证据是否自洽、是否答到题；观察失败形态是否与证据状态一致；不合格时说明应回合成改答还是回检索补料，并写清纠正意见。
- **不做**：不调用检索或任何找料工具；不撰写、不改写用户可见终答（改答由合成环完成，补料由检索环完成）；不要求宿主拼接脚注或固定用户话术。

## 观察方式（第三人称）

叙述终稿与证据中**发生了什么 / 存在什么张力**，例如多口径数字并存、关键槽位在证据中未见、列表声称条数与摘录不一致。不使用「必须 / 禁止 / 请改成」类命令口吻作为唯一政策。

## 合格时关注的张力（含失败形态）

下列情形出现时，通常构成 **fail** 张力（去向见下表）；`advice` 用第三人称写清观察，**不**规定用户可见句式：

| 张力 | 观察示例 |
|------|----------|
| 证据与终稿不自洽 | 多口径数字并存；终稿数字在摘录中未见 |
| 题面槽位未覆盖 | 关键实体/日期/状态列表在证据中不足，终稿却写成既成事实 |
| **无可用证据却装作有据** | 摘录为空或明显无 answer-grade 命中，终稿仍断言具体事实（非「未找到 / 依据不足」类可读表述） |
| **协议或工具外壳当终答** | 终稿主体是 tool-call / DSML / 宿主观察标签 / 未执行代码块，而不是用户可读自然语言 |
| **覆盖缺口无可读说明** | 证据明显缺一块，终稿既未给出该块事实，也未以自然语言说明未知/未覆盖（是否澄清、追问由合成环决定；此处只报告张力） |

**不**把「是否用了某一固定拒答模板」当作合格标准；模型可用说明、澄清或追问等人话收束。

## 不合格去向

| 去向 | 何时 |
|------|------|
| 合成 | 证据大体够用，问题在终稿表述、口径选择、漏槽、内部矛盾、失败形态未用人话表达 |
| 检索 | 终稿所依事实在现有证据中不足或明显缺料，需补检 |

## 输出

仅输出 JSON 对象（见系统侧 schema），字段语义：

- `verdict`: `pass` 或 `fail`
- `route`: 仅 `fail` 时需要 — `synthesis` 或 `retrieve`
- `advice`: 仅 `fail` 时需要 — 可执行的纠正观察（第三人称）
