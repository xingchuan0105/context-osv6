# 表格（管道行）怎么读

知识库表转文本后常见为 **Markdown 管道行**：`| 列1 | 列2 | … |`

本 spoke 只保留**通用读法**；表路径策略、多口径 few-shot、长 gotcha 见 **strategies-tables**。

## 通则

1. **一行 = 一条记录**（各列合在一起），不是「某一列单独一个对象」。
2. **格义 = 同一行 + 该列表头**；孤立数字不完整，完整事实是「计量对象 + 该格」。
3. **`grep` 的 `total_hits` = 命中行数**；某列名称是否重复，不改变行数含义。
4. **编码 / 活动号是标签**（如 `ROW-04`、`LPDT-04`），不是排序键。
5. **「第一个」**若指表中或流程先后：= **出现顺序**或显式序号列，**不是**标签字典序 / 数值最小。
6. **整行各列都相同**才算重复行；仅名称相同、其它列不同 → 多条记录。
7. **`truncated=true` 或 hits 达上限**：计数用 `total_hits`（或聚合查询结果）；`hits` 只是样本。
8. 左粗右细（阶段/类型 → 编码/状态）很常见；左侧相同、右侧不同 = 多条记录。

## 两例（虚构）

**行计数**

```text
问：状态「在库」有多少行？
回传：total_hits=12；多行品名相同、库位不同
读出：12 条记录；品名重复不合并行。
```

**表序（「第一个」）**

```text
问：角色 R 的第一个步骤？
回传出现顺序：先 STEP-03，再 STEP-04
读出：第一个 = STEP-03（步骤号不是排序键）。
```

## 行数 vs 去重（多口径）

同一回传上可以**同时**读出：

- **行口径**：`total_hits` / 行 COUNT  
- **去重口径**：按名称或活动号去重后的项数（须回传中真有可观察依据）

二者都是合法观察；完整写法是**分口径并列并标明统计键**，不是只交一个未说明口径的整数。  
展开与表路径 few-shot：**strategies-tables**（含 FS3b）。

## SQL 结果集（`struct_query`）

- **`row_count` = 结果集行数**，不是底表总行数。`SELECT COUNT(*)` 时 `row_count` 常为 1，**计数值在 `rows` 单元格**。
- `truncated=true`：`rows` 为样本；计数以聚合单元格为准。
- `ok=false`：先 `struct_catalog`（可用 `doc_ids` 收窄）再查；多 doc 同名表见 catalog 的 `ambiguous_relations`。

```text
回传：columns=["阶段","cnt"], rows=[["概念",3],["施工",5]], row_count=2
读出：合计 8 来自 3+5；row_count=2 只是结果集行数。
```
